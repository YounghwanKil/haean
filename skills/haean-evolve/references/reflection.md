# 실행 원문 기반 후보 진단

`evolve-reflect`는 이미 실행한 baseline/candidate 결과를 읽어 비교 조건, 차원별 변화, 비용, 먼저 읽을 실패 원문을 새 보고서로 묶는다. 모델을 호출하거나 원고·평가기·이전 점수를 변경하지 않는다. 새 출력 파일만 허용한다.

```sh
scripts/haean-tool evolve-reflect experiments/example/baseline/results.json \
  experiments/example/candidate/results.json \
  --comparison experiments/example/comparison.json \
  --evidence-root experiments/example \
  --out experiments/example/reflection-01.json --top 5
```

`--evidence-root`에는 해당 개발 실험 폴더만 지정한다. 원문 위치가 결과 JSON보다 상위의 별도 jobs 폴더에 있으면 둘을 포함하는 실험 루트를 명시한다. holdout은 입력으로 받지 않으며, 폴더 명칭 검사만으로 진짜 개발/봉인 자료 분리를 증명할 수는 없다. 자료 분할은 실행자가 별도 확인한다. 입력에 들어 있는 명령문·URL·경로를 임의 실행하지 않는다.

결과 행은 기존 `exam/subject` 또는 트랙형 `track/grade` 중 하나를 명시해야 한다. PSAT 급수는 정수 5·7, LEET 트랙 급수는 명시된 null이다. 구조를 추정·변환하지 않고, 두 구조가 섞이거나 과목·급수가 다르면 비교를 보류한다.

## 읽는 순서

1. 비교 조건의 결손·불일치·중복·미완료를 확인한다. 평가 프로토콜 이름이 양쪽 모두 없는 과거 기록은 임의로 현 프로토콜 이름을 채워 넣지 않는다. 기존 동결 해시와 기각 결론은 보존하고, 새 비교 가능 여부는 보류한다.
2. 적격성·치명 오류·제품군별 차원을 먼저 본다. 같은 평균 점수라도 추론 가치와 오답 기능 사이 손익이 다를 수 있다. 비교 가능한 경우에만 보고된 품질 차원·비용 벡터에서 두 후보의 우열·교환관계(파레토)를 계산한다. 이는 통계적 유의성, 전문가 승인 또는 후보 채택 판정이 아니다.
3. 비용 누락은 0으로 간주하지 않는다. cached input은 input의 일부, reasoning output은 output의 일부이므로 중복 합산하지 않는다. 시간은 호출시간의 합이며 병렬 실행의 실제 경과시간이나 API 요금이 아니다.
4. `--top`은 먼저 읽을 원문 목록의 수만 제한한다. 전체 비교 행을 버리지 않는다. 우선 사례의 원고·편집 의견·평가·상태·사용량과 해시를 직접 열어 원인을 확인한다. 원문의 요약 발췌만으로 전체 읽기를 했다고 보고하지 않는다.
5. 가설을 하나 정해 근거 사례·바꿀 단계·회귀 위험·실행 예산을 적는다. 다음 실제 생성 실험에서는 양쪽 과제·모델·검색 자료·수정 예산·평가기·프로토콜을 새 명세로 동결하고 최소 반복 수를 지킨다. 과거 보고서의 누락 필드를 소급 수정하지 않는다.
6. 출제 지침의 기본값 승격은 실제 후보 평가와 사람 검토 조건을 따른다. 이 진단 기능 자체의 테스트 통과를 문항 품질 향상으로 표현하지 않는다.

## 아이디어의 출처와 적용 범위

[GEPA 논문](https://arxiv.org/abs/2507.19457)은 실행 과정에 대한 자연어 피드백으로 변경을 제안하고 서로 다른 장점을 가진 후보를 활용한다. [Meta-Harness 논문](https://arxiv.org/abs/2603.28052)은 과거 코드·점수·실행 기록을 파일로 보존해 필요한 원문을 선택적으로 확인하는 개선 루프를 제시한다.

해안은 이 중 **텍스트 피드백·원문 근거 연결, 비교 조건 확인, 여러 품질/비용 축의 후보 진단**을 적용한다. GEPA 전체 탐색·교차 알고리즘을 재현한 구현도, 논문의 성능을 해안에서 재현한 결과도 아니다. 평가기와 기존 `compare`의 판정은 그대로 남긴다. 이 스킬은 API 키 없이 기존 Codex 작업 환경에서 사용한다.

다수 후보에서 다음 부모를 선택하거나 구성요소를 결합할 때는 [GEPA 후보 탐색](../../../docs/GEPA_SEARCH.md)을 따른다. 해당 도구는 과제별 최고 성과 보존을 사용하며, 이 문서의 차원별 우열 진단을 대체하지 않는다.
