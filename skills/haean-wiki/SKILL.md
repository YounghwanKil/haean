# 해안 지식 위키

원문 → SQLite 검색 DB → 지속적으로 갱신하는 `data/wiki`의 3층을 사용한다. DB는 원문을 찾는 도구이며 위키는 읽고 종합한 지식이다. 원문·카톡·문항·로컬 위키를 GitHub Wiki나 코드 저장소에 올리지 않는다. GitHub Wiki는 사용 설명서다.

## 자료를 지식으로 축적하기

1. `data/wiki/index.md`와 관련 페이지·동명 JSON 출처 기록을 읽는다. 없으면 `scripts/haean-tool wiki init`을 실행한다.
2. `search`로 원문을 찾아 **실제 관련 구간을 읽는다**. 검색 결과나 파일 목록만 보고 전문을 읽었다고 하지 않는다. 그림·표·수식이 근거라면 원본 시각 확인이 필요하다.
3. 이미 있는 지식에 새 자료를 합친다. 출처별 주장, 모델 종합, 미해결 모순, 적용 범위와 검증 한계를 구분한다. 서로 다른 검토자의 의견을 합의로 바꾸지 않는다. 기존 위키의 클론 지침이나 미검증 답을 모범 출제로 승격하지 않는다.
4. 아래 JSON 패킷을 로컬 작업 폴더에 작성하고 `wiki put --packet PATH`로 저장한다. 본문 주장에 `[1]` 등 근거 번호와 구간을 연결한다. 관련 페이지 양쪽을 필요에 따라 갱신한다. 각 페이지는 하나의 재사용 가능한 주제를 다룬다.
5. `wiki lint`를 실행하고 의미 충돌·낡은 주장·출처 결손은 직접 읽어 확인한다. lint는 해시·연결 검사이며 의미 검증을 대신하지 않는다.

```json
{
  "id": "sample-topic",
  "title": "주제",
  "summary": "색인에 표시할 한 문장",
  "status": "model-synthesis",
  "body": "자료가 말하는 사실 [1].\n\n## 한계\n아직 검증하지 않은 부분.",
  "sources": [{"path": "/absolute/source/path", "sha256": "실제로 계산한 SHA256", "locator": "시트·행 / DB record ID·ZIP 내부 경로 / 문서 구간", "usage": "development"}],
  "links": ["related-topic"]
}
```

상태는 `source-summary`, `model-synthesis`, `hypothesis`, `conflicted` 중 하나다. 모델이 전문가 승인 상태를 만들지 않는다. 개발 자료임을 실제 확인한 뒤 usage를 지정한다. holdout·봉인 평가·블라인드 정답은 위키로 유입하지 않는다. 도구의 usage 검사는 자기 선언 검사이며 데이터 분할을 자동 판별하지 않는다.

## 질문·출제에 사용하기

색인 → `wiki search --query "검색어"` → 관련 페이지 → 원문 순으로 읽는다. 사용한 페이지와 원문 근거를 답변에 연결한다. 출제에 활용한 페이지·메타데이터 사본과 해시는 해당 run에 남긴다. 위키는 출제 원칙·검토 이력의 참고이며 검증된 문항 few-shot을 대체하지 않는다. 블라인드 풀이자에게 위키를 전달하지 않는다. 이전 고정 평가 입력은 변경하지 않는다.

재사용 가치가 있는 답변은 사용한 원문을 근거로 `put`해 축적한다. 단순 질문마다 중복 페이지를 만들지 않는다. `put`은 이전 페이지를 history에 보존하고 index와 append-only log를 갱신한다. 기존 페이지를 임의 삭제하지 않는다.

## 유지보수

`wiki lint`의 stale-source는 변경된 원문을 다시 읽은 후 내용과 해시를 함께 갱신한다. 해시만 바꿔 통과시키지 않는다. orphan/broken-link는 관련 페이지를 읽고 연결한다. conflicted는 양쪽 근거와 해소 조건을 유지한다. 자동으로 모순이 없다고 선언하지 않는다. 파일은 Obsidian에서 읽을 수 있다. qmd·벡터 DB·API 키는 필수 구성요소가 아니다.
