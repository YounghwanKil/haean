# 문항 검토

1. `scripts/haean-tool check RUN DRAFT`를 실행해 현행 문항을 고정한다. 기계 검증은 문항의 의미상 정답을 증명하지 않는다.
2. **독립 풀이에는 새 컨텍스트 서브에이전트 haean_blind_solver를 사용한다.** 입력은 `blind-input.json`, `blind-instructions.md`, `blind-review-template.json`, `blind-review.schema.json`이다. 템플릿의 입력 연결 정보(`input_binding`)를 그대로 돌려주고 `result`에 풀이를 쓴다. 출제 대화와 정답을 상속하지 않는다. 새 컨텍스트가 불가능하면 `scripts/haean-tool blind RUN`으로 별도 Codex 세션을 사용한다.
3. 독립 풀이 결과가 나오면 `scripts/haean-tool editor-prepare RUN --blind RUN/blind-result.json`으로 편집 검토 입력을 고정한다. CLI `blind`는 성공 시 이 준비를 자동으로 수행한다. 외부 풀이 결과를 받았거나 다시 준비할 때는 명시적으로 실행한다. 새 준비는 이전 편집 결과를 무효화하므로 편집 결과 제출 직전에 다시 실행하지 않는다.
4. **haean_editor에게 편집 검토를 위임한다.** 현행 candidate와 context, 준비 결과의 `blind_snapshot` 사본, `editorial-instructions.md`, 관련 수정 사례와 새 `editorial-review-template.json`을 읽게 한다. 준비 기록은 `editor-review-request.json`에서 다시 찾을 수 있다. 출력은 `editorial-review.schema.json`에 맞춘 `editorial-result.json`이다. `result`에 검토를, `evidence`에 준비 당시 입력 연결 정보와 실행 주체를 기록한다. `check` 직후의 미준비 상태에서는 편집 결과를 만들지 않는다.
5. 검토 당시 candidate 해시로 `review-result`를 실행한다. 이 명령은 문항·지침·명세·요청 ID와 편집자가 대조한 독립 풀이의 연결을 검사한다. 예전 raw 결과에 최신 연결 정보를 붙여 재사용하지 않는다. A/B 오류는 수정 후 check와 독립 검토를 반복한다. 기본 수정은 2회까지이며 해결되지 않은 것은 이유와 함께 표시한다.

같은 check 요청에서 독립 풀이만 바뀌어도 새 편집 준비와 대조가 필요하다. 보존된 풀이 사본·결과 해시와 준비 ID가 맞지 않으면 과거 편집 결과를 거부한다. 이 연결은 어떤 입력을 검토 대상으로 삼았는지 확인하며, 실제로 읽고 판단했음을 증명하지는 않는다. 자동 단계형 생성은 매 수정마다 새 풀이·편집을 실행한다.

외부 검토 결과의 `producer.execution_mode`는 `external-attestation`이며 검토자, 요청 모델과 확인된 실제 모델을 구분한다. 확인하지 못한 모델 ID는 null로 둔다. 결과 해시는 실행기가 계산하므로 모델에게 계산시키지 않는다. 외부 검토자의 명시 기록은 실행 진위를 암호학적으로 증명하지 않는다. CLI `blind`는 실제 요청·응답 trace를 연결한다. 예전 연결 정보 없는 결과는 기록으로 보존하되 새 검토 통과 근거로 자동 승격하지 않는다.

LEET 추리논증의 편집 검토에는 `src/haean/prompts/leet_editorial.md`를 적용한다. `editorial-plan.json`과 `context.json`의 회차 소재·구조 컨텍스트가 있으면 함께 읽는다. 판단에 쓰이는 조건의 이관과 삭제, 주체·정의 변경에 따른 전체 동기화를 확인한다. 이 자료는 블라인드 풀이자에게 전달하지 않는다.

출제자가 자신의 정답을 가리고 다시 생각하는 방식은 독립 컨텍스트가 아니다. 같은 모델을 별도 세션으로 호출하는 것은 컨텍스트 분리이며 모델 간 독립성을 뜻하지 않는다.

위임 도구에 역할 선택 인자가 없으면 `role haean_blind_solver` 또는 `role haean_editor`로 지침을 읽어 작업 메시지에 넣는다. 블라인드 에이전트는 부모 대화를 상속하지 않으며, 참고 경로를 따라 candidate·context·원문 정답을 탐색하지 않도록 공개 입력만 전달한다. 파일 읽기까지 격리할 수 없으면 입력만 받는 별도 Codex `blind` 명령을 우선한다.

윤문은 주술 호응·수식 범위·대명사·번역투를 고치되 논리 연산자·수치·조문·직접 인용을 보존한다. 단순 스타일 제안은 C로, 해석을 바꿀 수 있는 모호성은 B 이상으로 구분한다. 검토자의 주장도 문면과 반례로 확인한다.

해설은 내부 검산 기록을 제외한 실제 출력 내용으로도 읽는다. 기본 HTML·HWP의 문제·표와 해설 본문(`explanation`, `judgments`의 `target/verdict/explanation`)에서 필요한 설명을 찾을 수 있는지, 미출력 배분명·보조표를 참조하지 않는지 확인한다. 출력 필드와 예외는 [양식의 검증 범위](../../docs/LAYOUT.md#검증-범위)를 따른다.

자료해석에서 출제자가 제시한 수치 오독의 작동 여부를 확인하려면 [수치 오답 경로 점검](../../docs/DISTRACTOR_CHECKS.md)의 선택 `distractor-check`를 사용할 수 있다. 정상값과 오독값이 달라도 선지의 진위는 같을 수 있다. 결과를 원자료·문면과 대조하고, 이 출제자용 자료는 블라인드 풀이에 전달하지 않는다.

누적 문항과의 자기 반복을 검토할 때는 [원문쌍 구조 검토](../../docs/NOVELTY_REVIEW.md)의 선택 `novelty-review`로 새 문항과 과거 문항의 전문을 별도 모델에게 전달할 수 있다. 검색 flag가 없는 상위 후보도 대조하며, 원형 ID만 주어진 경우 특정 사용 버전을 추정하지 않는다. 결과는 선택된 쌍에 대한 자문이다. 확인된 문제만 현 후보 해시에 연결한 피드백으로 남기고 기존 검토·사람 승인 상태와 구별한다.

이미 완성된 외부 문항의 검토 요청이면 입력 형식 때문에 검토를 멈추지 않는다. 먼저 읽을 수 있는 원문으로 검토하고, 구조화·내보내기가 필요할 때 스키마로 옮긴다. 필요한 원문·표·그림이 없으면 결손을 구체적으로 밝힌다.

팀원이 출력물을 풀고 의견을 돌려주는 작업은 [사람 검토 패킷](../../docs/HUMAN_REVIEW.md)의 `review-packet`과 `review-collect`를 사용한다. 인쇄 번호와 ID, 원 묶음의 버전 해시를 연결하고 실제 시간·정답 사전 열람 여부를 보존한다. 수집된 의견을 읽고 확인한 문항 문제만 `feedback --candidate-sha`로 원 묶음에 적용한다. 수집만으로 상태나 사람 체크포인트가 갱신되지 않으므로 A/B 의견을 수집한 채 최종 검토로 넘기지 않는다. 모델이 만든 의견은 `origin=model`로 유지하며, 응답 없음·미측정은 0이나 ‘오류 없음’으로 바꾸지 않는다.

원 검토본의 상태까지 보존한 새 회차 수정이라면 `feedback` 대신 [별도 수정 요청](../../docs/PRODUCTION.md#원-검토본을-보존한-수정-요청)을 사용한다. 수집 원문을 읽고 적용할 범위·작성 주체·유지할 조건을 명시한 뒤 요청을 만든다. C급 편집 요청도 실행할 수 있으며, 새 검토 전까지 원고의 오류가 해결됐다고 표시하지 않는다.
