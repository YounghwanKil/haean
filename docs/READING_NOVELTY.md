# 언어이해 누적 문항과 반복 검사

언어이해도 로컬 `data/generated.sqlite`에 생성 이력을 기록한다. 추리논증용 `Item`으로 바꾸지 않고, 공통지문과 세 문항을 그대로 저장한다. 등록·문자 유사도 검색·원문쌍 모델 검토는 서로 다른 작업이며 독창성 승인이나 정답 독립 풀이를 대신하지 않는다.

## 입력과 사용 순서

| 명시한 입력 | 읽는 범위 |
|---|---|
| 언어이해 `book.json` 또는 해당 book 폴더 | 검증된 book의 모든 지문과 문항 |
| `reading prepare`로 만든 제작 run | 계획된 모든 지문의 현재 시도 원고. 미작성 지문이 있으면 중단하며 `--passage-id`로 작성된 지문을 선택할 수 있음 |
| 제작 run의 개별 attempt 폴더 | 그 시도에 고정된 한 지문과 세 문항 |

일반 추리논증·PSAT run과 조립된 회차 입력도 계속 지원한다. 입력 폴더를 재귀 순회해 임의 원고·holdout·실험 결과를 모두 등록하는 기능은 아니다.

```sh
# 이전에 실제로 만든 원고를 명시 등록한다.
haean tools novelty-index runs/reading-previous/book.json
haean tools novelty-memory --exam leet --subject 언어이해 --out runs/reading-memory.json
haean tools novelty-get --exam leet --subject 언어이해 --item READ-Q01 --all-versions --out runs/reading-history.json

# 새 제작 run의 현재 원고를 누적 이력과 대조한다.
haean tools novelty-check runs/reading-next --out runs/reading-next-novelty.json

# 아직 나머지 지문을 작성 중이면 지문 하나만 지정한다.
haean tools novelty-check runs/reading-next --passage-id READ-P01 --out runs/reading-p01-novelty.json

# 여러 지문이 있으면 한 지문을 선택하여 원문쌍 모델 검토를 진행한다.
haean tools novelty-review runs/reading-next --passage-id READ-P01 --out runs/reading-p01-pairs

# 검토한 새 원고도 명시적으로 누적한다.
haean tools novelty-index runs/reading-next
```

`novelty-index`도 `--passage-id`를 지원한다. 선택한 세 문항을 등록한 것이 나머지 지문이나 회차의 검토 완료를 뜻하지 않는다.

`READ-Q01`과 `READ-P01`은 예시 ID다. 실제 원고의 문항 ID·지문 ID 또는 색인에서 반환된 ID를 쓴다. 과거 문항 ID가 없는 book에는 자동으로 만든 버전 한정 ID가 표시된다. `novelty-check`는 해당 과목의 **등록된 과거 이력**에서 후보를 찾는다. `novelty-review`도 선택한 지문과 과거 이력의 쌍만 다룬다. 아직 등록하지 않은 새 문항끼리의 반복이나 같은 지문 세 문항의 역할 중복은 편집 검토에서 별도로 확인한다.

## ID, 공유 지문, 원문 연결

새 제작물은 계획에 있는 문항 ID를 유지한다. 번호 재배치는 ID 변경이 아니며, 같은 시험·과목·ID는 수정 계보로 취급한다. 다른 새 문항에 같은 ID를 다시 쓰면 같은 계보로 제외되므로 새 문항에는 새 ID가 필요하다.

옛 book에 문항 ID가 없으면 book의 원바이트 SHA와 지문·문항 위치로 식별한다. 이 ID의 범위는 `book_version`이며, 다른 판과의 수정 계보를 보증하지 않는다. 새 ID를 원문에 몰래 끼워 넣거나 번호가 같다는 이유로 판을 합치지 않는다.

각 저장 항목은 선택한 문항의 위치와 **공통지문·형제 문항 세 개 전부**를 포함한다. 지문이나 다른 형제 문항이 달라지면 대조 문맥도 달라지므로 저장 버전이 바뀐다. 원본 book의 SHA와 위치도 기록한다. 동일 문항이 attempt와 조립본에 함께 들어 있어도 안정 ID는 같지만, 출처가 다른 저장 버전으로 남을 수 있다. 이를 새 문항 수로 합산하지 않는다.

`content_sha256`는 지문·세 문항·선택 위치의 해시이고, DB의 `sha256`는 출처 결속도 포함한 전체 저장 항목의 해시다. 원본 book이나 출처 기록이 바뀌면 문항 문면이 같아도 저장 버전은 달라질 수 있다. 두 값을 같은 의미로 비교하지 않는다.

`novelty-get`의 `source_resolution`은 기록한 book의 원바이트 SHA·지문·문항 위치와 실제 파일을 대조한다. 파일이 바뀌거나 없으면 미해소 상태로 남는다. 일반 run의 `revision-*` 보관 경로를 언어이해 원고에 임의로 적용하지 않는다. 저장 payload는 읽을 수 있지만, 미해소 파일을 그 판의 확인된 원본으로 인용해서는 안 된다.

새 제작 조립본의 `verification.json`은 원고·계획·시도와 대조한다. 옛 회차 옆에 있던 검토 메타데이터는 `legacy_unverified_metadata`로 구분해 경로·해시만 보존하고, 승인이나 native 검증 주장까지 채택하지 않는다. 그 메타데이터가 원본 book SHA를 명시했다면 일치는 확인한다.

공통지문이 같다는 사실만으로 세 문항을 반복 문항으로 판정하지 않는다. 검색은 의도한 지문 공유를 따로 처리하고 질문별 인지과제·해설·선지의 유사 후보를 제시한다. 공유 지문 안에서 같은 결정적 추론이나 오답을 반복하는지는 원문으로 확인한다.

## 선택 원문쌍 모델 검토

`novelty-review`는 언어이해에서 한 지문×3문항을 받는다. 입력에 지문이 여러 개 있으면 `--passage-id`가 필요하다. 전 회차를 한 번에 모델에 넣거나 지문을 임의로 고르지 않는다. 기존 상위 후보와 flag의 선정 규칙, 최대 12쌍·입력 500,000바이트 제한을 유지한다. 범위를 넘으면 경고 후보를 잘라내지 않고 중단한다.

다지문 book의 모델 검토에는 원문 지문 ID가 필요하다. 지문 ID가 없는 옛 book도 색인·문자 비교는 가능하지만, 이 명령으로 특정 지문을 고를 수는 없다. 검토를 위해 원본에 ID를 임의로 덧붙이지 않는다.

모델에는 양쪽의 공통지문·세 문항 전문과 비교 대상 문항을 함께 전달한다. 답·해설은 작성자의 주장으로 취급한다. 모델이 제시한 인용과 JSON 위치, 버전 해시, 비교 대상 문항의 네 오답 역할을 기계적으로 검증한다. 이 검증은 모델의 의미 판단이 옳다는 보증은 아니다.

원문쌍 검토를 블라인드 풀이에 섞지 않는다. 기존 원고·풀이·편집 결과·누적 DB를 자동 변경하거나 승인을 만들지 않는다. 실제 호출·사용량·결과와 실패는 새 출력 폴더에 남고 자동 재시도하지 않는다. 자세한 공통 계약은 [선택 원문쌍 구조 검토](NOVELTY_REVIEW.md)를 따른다.

이 연결은 언어이해 이력을 검색하고 근거를 보존하는 기능이다. 100번째 이후 자기 반복 감소, 전문가 수준의 출제, 실전 난도, 고정 평가 점수 향상을 검증한 결과로 해석하지 않는다.
