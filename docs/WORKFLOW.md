# 팀 작업법

코드와 지침은 GitHub로 공유하고, 원문 자료는 팀이 접근할 수 있는 별도 저장소에서 배포합니다. 팀원은 같은 파일을 `./haean tools import`하면 파일 해시 기반 출처 ID를 재현할 수 있습니다. 원본 절대 경로는 로컬 DB에만 남습니다.

권장 변경 단위는 '관측한 오류 하나 + 일반화한 규칙 + 검증 사례'입니다. 단지 초안이 마음에 들지 않는다는 이유로 프롬프트 전체를 교체하지 않습니다. `src/haean/prompts/leet.md`, `psat.md`는 제품 규칙, `editor.md`는 교차 검토 기준, `haean.md`는 공통 생성 계약을 담당합니다.

1. 담당자가 브랜치에서 코드·지침을 고칩니다.
2. `pytest -q`와 실제 소규모 출제를 실행합니다. 실제 Codex/Astra 출제를 실행하지 않았다면 기록합니다.
3. PR에는 구체적인 실패 예와 수정 후 행동, 검증 결과를 적습니다. 팀 원문을 그대로 공개하지 않습니다.
4. 새 피드백은 `./haean tools feedback`으로 기록합니다. 의견 충돌은 문항의 명시 조건과 반례로 해결합니다.

## 한글 도구 연결

`candidate.json`의 `items`는 발문·지문·보기·표·선지·정답·해설을 분리합니다. 기존 Java 도구 담당자가 이 스키마를 읽는 어댑터를 구현하면 됩니다. 연동 전에 필요한 것은 Java 프로젝트/API, 템플릿의 필드·누름틀 명세, 수식/표 객체 입력 방식입니다. 폰트 ZIP은 목록만 확인하며 설치하지 않습니다.

현재 HTML은 내용 검토용입니다. HWP 출력·페이지 수·20p 양식·수식 개체 유지에 대한 검증은 아직 수행하지 않았습니다.

## 한국어 윤문 도구

대화에서 제안된 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)는 한국어 번역투 탐지·윤문 도구입니다. vendor/im-not-ai submodule과 humanize-korean 스킬로 연결했습니다. 일반 글의 표현 개선 기준을 시험 문제에 그대로 적용하면 논리 연산자·조건 범위·직접 인용이 달라질 수 있어, 해안은 자체 편집 검토 후 정답 재검증 절차를 사용합니다. 윤문할 때는 '모든/어떤', 부정, 날짜, 수치, 정의, 조문 번호를 보호하고 수정 뒤 풀이 검토를 다시 거쳐야 합니다.
