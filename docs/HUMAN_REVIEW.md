# 사람 검토 패킷

검토자가 푼 출력물과 돌아온 의견을 같은 문항 버전에 연결한다. LEET 추리논증과 PSAT 5·7급의 candidate run 또는 `assembled.json` 회차, LEET 언어이해의 텍스트형 `book.json`을 지원한다. 언어이해는 별도 어댑터로 읽으며 추리논증 문항으로 변환하지 않는다.

## 준비와 전달

Codex 대화창에서 “이 회차를 사람이 풀 수 있게 문제와 해설을 분리하고 검토 양식을 만들어줘”라고 요청할 수 있다. 직접 실행할 때는 일반 터미널에서 다음 명령을 사용한다.

```bash
haean tools review-packet runs/회차/assembled.json --out runs/검토패킷
# 개별 또는 2~4문항 묶음도 지원
haean tools review-packet runs/문항묶음 --out runs/묶음검토패킷
# 언어이해 공통지문과 문항을 함께 전달
haean tools review-packet runs/leet-reading/회차/book.json --out runs/언어이해검토패킷
```

새 출력 경로를 사용한다. 원본 candidate·brief·status는 바꾸지 않는다. 출력에는 학생용 문제 HTML/JSON, 별도 해설, 빈 응답 JSON과 스키마, 문항 번호·ID·부모 묶음·파일 해시를 연결한 manifest가 들어간다. 그림이 있으면 렌더한 학생용 이미지도 포함한다. 내부 제작 메모나 원본 경로는 학생용 파일에 넣지 않는다.

독립 풀이를 받을 때는 **학생용 폴더만 먼저 전달**한다. 해설은 풀이 뒤에 전달하고 응답에는 사전 정답 열람 여부를 기록한다. 전달 시점이 필요하면 별도 운영 메모에 남긴다. 전체 패킷은 운영자가 보관한다. 이 HTML은 검토용이며 실제 한글 양식 출력·인쇄 배치 확인을 대신하지 않는다.

## 언어이해의 공통지문과 식별자

`book.json` 또는 그 파일이 있는 디렉터리를 지정한다. 여러 원고 형식이 같은 디렉터리에 있으면 파일을 직접 지정한다. 지문마다 고유 ID·문단·세 문항이 있고 문항 번호는 원문 순서대로 1부터 이어져야 한다. 10지문·30문항 회차와 더 작은 파일럿을 같은 방식으로 처리한다. 구조화된 그림·표 등 지원하지 않는 표시 필드가 있으면 누락시키지 않고 오류로 알린다.

학생용에는 공통지문을 세 문항 앞에 한 번 표시하고, 발문·보기·선지만 담는다. 제작 제목·영역·출처·인지과제·난도·정답·해설·검토 메모는 학생용에 넣지 않는다. 검토자용에는 정답·본 해설·선지별 해설과 반대 해석을 별도로 보관한다.

기존 원고의 정확한 `<u>…</u>` 표시는 밑줄로 보존한다. 닫히지 않거나 중첩된 밑줄, 빈 구간, 속성이 붙은 태그는 출력 전에 거절한다. 다른 HTML은 글자로 표시하며 실행하지 않는다.

원문에 개별 문항 ID가 없을 수 있어 패킷의 `item_id`는 **해당 book 버전의 검토용 식별자**로 만든다. 원본의 안정 ID나 인쇄 번호와 같은 것으로 취급하지 않는다. manifest와 수집 결과에는 전체 book 해시, 지문 ID, JSON 문항 위치와 실제 번호를 함께 기록한다. 원문에 문항 ID가 있으면 별도 `source_question_id`로 보존한다.

공통지문 의견은 응답의 `location`에 지문 범위를 적는다. book의 지문·문항·답·해설·배치가 바뀌면 이전 패킷에 대한 새 수집은 거절된다. 지문 수정 뒤에는 연결된 세 문항을 모두 재검토한다. 이전 의견을 새 버전에 자동 승계하거나 새 의견으로 바꾸지 않는다.

## 의견 회수

사람은 자연어 메모로 의견을 보내도 된다. 총괄이 실제 원문을 보존하고 응답 양식에 옮긴 뒤 누락된 값은 null로 둔다. 검토자가 말하지 않은 시간·완료 여부·선지 판단을 만들어 채우지 않는다. 모델이 추가한 의견은 별도 `origin=model` 응답으로 남긴다.

응답에는 다음을 기록한다.

- 검토자와 `origin`(human/model), 검토 패킷의 manifest 해시
- 인쇄 번호와 문항 ID, 검토 완료 여부, 사전 정답 열람 여부
- 선택한 답, 실제 측정한 풀이시간·수정 검토시간(초)
- 선지별 판단 근거, 오류의 A/B/C 등급·위치·원문 구절·이유·수정 제안

부분 검토를 허용한다. 누락 또는 미완료를 ‘오류 없음’이나 0초로 집계하지 않는다. `origin=human`은 작성자에 대한 명시 기록이며 도구가 실제 사람의 작성이나 전문성을 인증하는 것은 아니다.

```bash
haean tools review-collect runs/검토패킷 /받은경로/검토응답.json
```

명령은 번호·ID·패킷 파일·원본 문항 해시를 대조하고 응답 원문과 요약을 보존한다. 같은 응답의 재수집은 중복 기록을 만들지 않는다. 그동안 문항이 바뀌었다면 현행 버전에 의견을 붙이지 않고 거절한다. 과거 출력물과 의견은 그대로 보관하고 새 버전을 검토한다.

## 수집 이후의 수정

수집은 원문과 연결을 보존하는 단계다. **수집만으로 원 묶음의 상태, 기존 feedback, human-checkpoint가 갱신되지 않는다.** 총괄은 수집 결과의 미완료 문항과 A/B 의견을 먼저 확인한다. 문면과 대조해 확인한 문제를 해당 원 묶음에 기록하고 수정한다.

아래 `feedback`·`human-checkpoint` 명령은 기존 candidate run에 적용한다. 언어이해에는 적용하지 않는다. 언어이해 의견은 수집 결과의 book 해시·지문·문항 위치를 기준으로 검토하고 별도 수정본과 독립 풀이·편집 결과를 남긴다. 이 연결은 언어이해 고정 평가기나 사람 승인 기능의 지원을 의미하지 않는다.

```bash
haean tools feedback PARENT_RUN --item ITEM_ID --reviewer 실제검토자 \
  --origin human --severity B --candidate-sha 검토당시_PARENT_SHA \
  --file 확인한문항의견.txt
```

회차의 `items/NN`은 재조립할 수 있는 편집 뷰다. manifest·수집 결과에 연결된 `parent_run`과 **부모 candidate의 해시**를 사용한다. 번호를 ID 끝자리로 추정하지 않는다. `feedback --candidate-sha`는 옛 출력물에 대한 의견이 새 문항에 붙는 것을 차단한다. 이 옵션을 생략한 기존 명령은 제출 시점의 해시만 기록하며 검토 버전 확인은 `submission_only`로 남는다.

확인한 A/B는 수정 필요 상태로 기록하고 수정·독립 풀이·편집을 다시 수행한다. 체크포인트를 넣어도 남은 수정 필요 상태와 검토 오류는 해제되지 않는다. 실제 사람 검토가 끝난 문항 묶음에만 `human-checkpoint`를 기록한다. 부분 검토로 묶음 전체가 완료됐다고 쓰지 않는다.

공통으로 재사용할 교훈은 개별 수정과 구별해 원문 사례·가설·적용 범위를 로컬 위키에 남긴다. 수집 건수, 모델 검토, 실제 전문가 검토, 실측 난도·선택률, 한글 출력 검증은 별도 결과다. 패킷·응답·로컬 위키 원문은 공개 Git에 올리지 않는다.
