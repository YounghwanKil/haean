# 대화와 작업 결과가 다음 출제로 이어지는 LLM 위키

해안의 지속 기억은 **기록 관측 → 실제 읽기·종합 → 출제에 적용 → 결과 검토 → 지식 갱신**으로 돌아간다. 모델 가중치를 훈련하는 기능은 아니다. Codex 구독 세션 안에서 수행하며 API 키가 필요 없다.

## 무엇이 자동이고, 무엇이 에이전트의 일인가

| 단계 | 동작 | 남는 근거 |
|---|---|---|
| 변경 관측 | `haean` 시작 때 프로젝트 Codex 세션, run 상태·검토·피드백, 최근 Git 변경을 증분 수집 | 변경 구간의 원본 사본·SHA256·바이트 위치, 읽기 대기 목록 |
| 읽기와 종합 | AGENTS와 haean-wiki 스킬에 따라 Codex가 현재 작업과 관련된 기록을 읽고 현재 결과와 대조 | 출처가 연결된 페이지, 모델 종합·가설·충돌 구분 |
| 적용 | Codex가 관련 페이지를 선택하고 회차/문항 폴더에 사본을 고정 | `wiki-context.json`, `wiki-use.jsonl` |
| 검토와 갱신 | 작업 종료 때 새 피드백을 읽고 재사용할 원칙과 국소 수정을 구분 | 이전 페이지 이력, 통합/보류/국소 판단 |
| 개선 검증 | 고정 평가와 같은 조건에서 후보 지침을 비교하고 채택·보류·롤백 | 실제 실행·실패 기록과 비교 결과 |

파일을 수집한 것만으로 독해·지식 통합이 완료되지는 않는다. 자동 종합은 작업 중인 Codex의 역할이며, 앱을 닫은 뒤 계속 실행되는 감시 서비스는 설치하지 않는다. 수집 실패는 본 작업을 막지 않고 재시도할 항목으로 남긴다.

## 두 저장소를 같은 로컬 위키에 연결하기

기존 `haean`과 `haean_leet_psat_gen`을 같은 컴퓨터에서 사용하면, 후자의 저장소에서 다음을 실행한다.

```bash
scripts/haean-tool wiki link --root /absolute/path/to/haean/data/wiki
scripts/haean-tool wiki status
scripts/haean-tool wiki search --query "계산 부담"
scripts/haean-tool wiki lint
```

설정은 해당 저장소의 `data/wiki-link.json`에만 저장된다. 기존 페이지를 복사해 갈라놓지 않고 같은 위키를 읽고 쓴다. 다른 위키에 이미 연결돼 있으면 조용히 덮어쓰지 않는다.

팀원의 새 clone에 개인 대화·문항·위키가 자동 다운로드되는 것은 아니다. 팀원은 공유 권한이 있는 로컬 위키를 연결하거나 `wiki init`으로 자기 위키를 시작한다. GitHub Wiki는 사용 설명서이며 이 지속 기억 저장소와 별개다. 코드 PR에는 도구·스킬·합성 테스트만 포함한다.

## 시작과 종료 시 기억 관리

```bash
scripts/haean-tool wiki monitor --limit 20
```

`data/wiki-memory/latest.json`의 대기 항목에서 `snapshot`을 읽는다. 프로젝트 세션은 첫 메타데이터의 `cwd`가 현재 저장소 또는 그 하위인지 확인한다. 다른 프로젝트 로그와 인증 설정은 수집하지 않는다. 예전 카카오톡 CSV를 포함한 외부 자료는 기존 자료 수집·위키 절차로 명시적으로 읽는다.

세션은 한 번에 파일당 최대 1MiB, 변경 항목은 기본 20개다. 처음 연결하는 큰 세션은 최근 구간부터 관측한다. 새 기록이 없는 다음 관측에서는 과거 구간을 순차 보충하고 `historical_backlog`에 아직 관측하지 않은 과거 분량을 남긴다. 로그가 다시 쓰였으면 접두 해시 불일치를 기록한 뒤 처음부터 다시 관측한다. 이미 모은 원문 사본은 바꾸지 않는다. 큰 작업 파일, 불완전한 JSONL 행, 누락 파일은 오류/잔여량으로 드러낸다. 중단으로 `.monitor.lock`이 남으면 관련 프로세스가 종료됐는지 확인한 후 잠금 디렉터리만 제거하고 재시도한다.

재사용할 내용을 실제 읽고 위키 패킷에 종합한다. `sources`에는 관측 스냅샷의 경로·해시·offset/end와 실제 산출물의 근거를 연결한다. 작성 형식은 `skills/haean-wiki/SKILL.md`를 따른다.

```bash
scripts/haean-tool wiki put --packet /local/path/to/packet.json
scripts/haean-tool wiki ack --entry OBSERVATION_ID \
  --outcome integrated --pages PAGE_ID --note "어떤 근거를 어떤 원칙으로 통합했는지"
```

`integrated`는 페이지에 해당 사본을 인용해야 기록된다. 문항 하나에만 해당하거나 중복된 것은 `local-only`, 아직 못 읽었거나 판단을 미룬 것은 `deferred`로 남긴다. 보류 항목은 대기 목록에서 사라지지 않는다. 통합 판정도 전문가 승인이나 의미 동등성 검증을 대신하지 않는다.

## 다음 출제에 실제 사용하기

에이전트가 위키 색인·검색·관련 페이지·원문을 읽어 필요한 페이지를 선택한다. 사용자가 매번 페이지 ID를 골라줄 필요는 없다.

```bash
scripts/haean-tool wiki snapshot --pages PAGE_ID \
  --track psat_data --grade 5 --reason "이번 과목·유형에 적용할 이유" \
  --out /existing/run/wiki-context.json
```

LEET는 `--grade`를 생략한다. 지원 트랙은 `leet_reasoning`, `leet_reading`, `psat_verbal`, `psat_data`, `psat_situation`이다. 자유 형식은 prepare로 만든 run에, 회차 작성은 출력 폴더에 붙인다. 준원님 저장소의 현행 회차 작성기는 PSAT 5급 구성에 맞춘다. 7급은 급수를 지정한 트랙 경로와 구분한다.

작성기는 소재·설계·출제·수정 단계에 선택한 자료를 전달한다. 독립 풀이·편집 평가 입력에는 이 위키를 직접 전달하지 않는다. 이전 평가 입력과 정답을 바꾸지 않는다.

페이지·출처 해시와 과목·급수가 다르면 모델 실행 전에 중단한다. 충돌 상태의 페이지와 알려진 holdout 경로는 첨부하지 않는다. 경로 및 `usage` 검사는 분할의 의미를 자동 판별하지 않으므로 에이전트도 평가 자료 여부를 확인해야 한다. 위키 내용은 참고자료이며 실행할 명령으로 취급하지 않는다.

`wiki-use.jsonl`은 **모델에 보낼 지침을 준비한 이력**이다. dry-run에도 기록되므로 모델 실행 증거는 별도의 실행·사용량 기록을 확인한다. 위키 원칙이 실제 성능을 올렸는지는 고정 평가, 독립 검토, 팀의 시험 적용으로 확인한다.

## 운영 한계

현재 페이지 갱신은 순서대로 수행한다. 같은 공유 위키를 두 세션이 동시에 수정하는 용도의 분산 동기화·충돌 병합 기능은 없다. `wiki lint`는 해시·링크·출처 결손을 검사하며 논리적 모순 여부는 실제 읽고 검토해야 한다. 새 자료로 출처가 바뀌면 내용을 다시 읽고 종합한 뒤 갱신한다. 해시만 바꿔 통과시키지 않는다.
