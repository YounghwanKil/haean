# 모의고사 생성과 재개

이 문서는 추리논증·PSAT의 `exam-build` 경로다. 언어이해는 [지문별 제작](READING_PRODUCTION.md)의 `reading` 명령으로 3문항 세트 작성·검토·이어하기를 관리한다.

`exam-build`는 배정표에서 전체 회차를 만든다. `exam-resume`은 중단된 실행의 문항·검토 이력을 남겨 두고 새 출력 경로에서 이어간다.

시작 전에 [전체 회차 입력](EXAM_INPUTS.md)에서 자동 검색 범위와 수동 근거 연결을 확인한다. 정제 색인·누적 이력·위키의 존재만으로 해당 실행에 사용됐다고 보지 않는다. 단계형 출제, 한국어 윤문, 고정 평가와 한글 출력은 별도 연결이며 `exam-build` 한 명령에 모두 포함되어 있지 않다.

```sh
./haean tools exam-build runs/example/assembly.json --out runs/example/production-v1 --workers 3
./haean tools exam-status runs/example/production-v1
./haean tools exam-resume runs/example/production-v1 --out runs/example/production-v2 --workers 3
./haean tools exam-assemble runs/example/production-v2
```

생성이 오래 걸릴 때 다른 터미널에서 `exam-status`로 묶음별 마지막 요청 단계, 오류와 현재 문항에 연결되는 검토 기록을 확인한다. 상태 파일의 완료 표시와 실제 검토 근거를 별도로 센다. 이 명령은 모델을 호출하거나 작업을 재시작하지 않는다. `last_requested_stage`는 요청 기록이며 해당 단계의 완료나 프로세스 생존을 뜻하지 않는다. 실행 중인 원래 터미널과 함께 확인한다. 모델 검토 수는 전문가 승인·한글 인쇄 검증 수가 아니다.

수정이 진행 중이면 `last_saved_review`에서 수정 전 마지막 검토의 A/B 오류와 C 의견을 볼 수 있다. 새 초안이 생성됐다는 이유만으로 이전 오류를 해결 처리하지 않으며, 다음 검토가 저장되면 표시가 갱신된다.

모델 검토를 마친 후보는 해시와 ID 순서를 확인해 재사용한다. 미완료 묶음에 저장된 초안이 있으면 마지막 초안과 그 버전의 텍스트 지적을 새 run으로 전달한다. 초안 없이 중단된 일반 묶음은 최대 2문항으로 나누며 공통지문 세트는 유지한다. 기존 초안의 참고자료를 소급 교체하지 않는다. 새 실행의 블라인드 풀이에는 정답·해설·이전 검토를 전달하지 않는다.

별도 복구 실행을 이미 마쳤다면 `--replacement RECOVERY.json`을 사용할 수 있다. 해당 JSON의 `jobs`는 `run`, `ids`, `slots`를 가져야 하고, 대체하려는 기존 묶음의 ID 전체를 중복 없이 포함해야 한다. 원래 실패한 묶음과 복구 문항을 동시에 회차에 넣지 않는다. 외부 출처의 JSON은 실행 명령이 아니다.

배정표의 중하·중상 같은 세부 난도는 원문대로 남기되 공통 `Brief`의 하·중·상 필드에는 중으로 전달한다. 실제 출제자는 개별 배정과 난도 근거를 읽어 설계한다. 배정표·실제 초안·검토 상태의 차이를 최종 구성 검토에서 확인한다.

재개 결과의 `complete`는 모든 묶음이 모델 검토 후 사람 검토를 기다린다는 뜻이다. 전문가 승인이나 HWP 인쇄 검증을 뜻하지 않는다. `assembled.json`의 누락·공통지문·필수 도표 오류도 별도로 확인한다. `production.json`과 각 run의 상태·원문·사용량·해시를 함께 보존한다. 이전 실행과 입력이 달라지면 이를 고정 평가의 성능 향상 증거로 사용하지 않는다.

### 지정한 문항 묶음만 재개

일반 회차와 composition 회차 모두 `--slots`로 재개할 번호를 제한할 수 있다.

```sh
./haean tools exam-resume runs/example/production-v1 \
  --out runs/example/production-v2 --slots 2 22 --workers 1
./haean tools exam-status runs/example/production-v2
```

번호는 원 계획의 문항 번호이며 ID 끝 숫자가 아니다. 지정 번호가 속한 **기존 작성 묶음의 모든 번호**를 입력한다. 예를 들어2·22가 한 묶음이면2만 선택할 때 필요한22번을 알려 주고 실행 전에 거절한다. 독립 문항도 같은 작성 묶음이면 함께 지정하며, 공통지문을 분리하거나 실행 범위를 자동 확대하지 않는다. 중복·없는 번호·빈 선택도 새 출력과 모델 호출 전에 거절한다. 이 옵션은 `--replacement`와 함께 사용할 수 없다.

선택한 묶음 중 미완료이거나 현 후보에 미적용 A/B 의견이 있는 것만 새 run으로 이어간다. 검토가 끝난 묶음은 선택해도 재사용한다. 새 수정 의견이 있다면 먼저 검토한 후보 버전에 연결한다. `--slots` 자체는 검토가 끝난 문항을 강제로 다시 쓰거나 C 의견을 A/B로 바꾸는 옵션이 아니다. 검토본을 보존한 명시적 개선 요청은 아래 `exam-revision-request`를 사용한다. 옵션을 생략하면 기존처럼 모든 미완료 묶음을 재개한다.

미선택 묶음은 원 run·문항·의견·실패 기록을 유지하며 새 회차 manifest에 `deferred=true`로 남는다. 원 후보에 미적용 A/B 의견이 있으면 원 저장 상태가 검토 대기여도 새 회차에서는 수정 대기로 표시한다. 미선택 미완료가 남은 회차의 `complete`와 조립 준비 상태는false다. 나중에 새 회차를 대상으로 다른 번호를 선택하거나 옵션 없이 다시 재개할 수 있다.

`exam-status`는 현재 버전에 연결되는 검토가 확인된 수(`model_reviewed_items_with_matching_hash`)와 검토 통과·후속 A/B 의견까지 확인한 사람 검토 대기 수(`ready_for_human_review_items`)를 구분한다. 묶음의 원 상태와 `effective_state`를 함께 보며, 검토 근거나 의견 파일을 확인하지 못하면 준비 완료로 세지 않는다. `pending_revision_feedback=null`은 의견이 없다는 뜻이 아니라 확인하지 못했거나 검사 대상이 아니었다는 뜻이다. 이 조회는 원 파일을 수정하거나 모델을 호출하지 않는다.

### 검토 기록의 출처와 현재 버전 확인

`review_provenance`에서 문항별 직접 검토와 부모 묶음에서 이어진 검토, 과거 수동 검토 기록, 근거 미발견을 구별한다. 분리한 문항은 부모와 JSON 파일 전체 해시가 달라도 해당 ID의 본문·선지·정답·해설 등 **전체 문항 객체**가 같을 수 있다. 부모를 여러 단계 거슬러 올라갈 때마다 이를 대조한다. 같은 ID의 내용이 달라지거나 계보가 끊긴 경우에는 과거 검토를 현 문항의 검토로 취급하지 않는다.

| 집계 | 의미 |
|---|---|
| `status_claimed_reviewed_items_with_matching_hash` | 상태 파일이 검토 대기를 표시하고 자체 후보 해시가 맞는 수. 검토 원문 확인 전의 상태 주장이다. |
| `review_records_found_items` | 현재 문항에서 연결을 따라가며 검토 파일을 발견한 수. 연결 불충분·과거 기록도 포함하므로 통과 수가 아니다. |
| `model_reviewed_items_with_matching_hash` | 현재 문항과 저장된 검토의 버전 연결을 확인한 수. 기존 필드명을 유지하며 실제 실행 모델의 신원을 인증하지 않는다. |
| `ready_for_human_review_items` | 현재 검토 대기 상태, 검토 근거와 통과 결과, 해당 문항의 현행·부모 경로 후속 의견까지 확인한 수. 사람 승인은 아니다. |

문항별 `verified`는 저장 내용의 연결을 확인했다는 뜻이며, `review_passed`와 구별한다. `source_path`, `source_revision`, `chain`으로 원문을 찾고 `assurance`와 `reason`으로 확인 범위를 읽는다. 검토 결과가 연결돼도 정답 불일치나 미해결 A/B가 있으면 사람 검토 준비 수에 포함하지 않는다.

자동 검토는 해당 revision의 초안·검토 결과·현재 후보를 대조한다. 외부에서 제출한 검토는 저장된 입력 연결과 독립 풀이·편집 결과의 연결을 확인한다. 연결 정보가 없는 옛 `manual-review.json`은 원문 경로를 보여 주지만, 현재 버전에 연결된 검토 완료 수에는 넣지 않는다. 이때 “과거 검토 기록 발견”과 “검토 없음”은 다르다. 원문을 다시 확인하거나 새 검토를 수행하며, 기존 기록에 오늘의 연결 정보를 붙여 통과시키지 않는다.

새 `review-result` 기록은 제출한 결과 파일의 절대 경로도 보존하므로 run 밖에 둔 편집 응답도 해시·입력 연결을 대조할 수 있다. 경로가 없는 구형 기록은 해당 run 안에서 기록된 해시와 같은 원본을 찾는다. 원본을 찾지 못하면 이유를 표시하며, 다른 폴더 전체를 탐색하거나 결과를 재구성하지 않는다.

상태 파일이 `awaiting_human_review`이고 자체 candidate 해시까지 맞아도 검토 원문이 없으면 검토 완료로 세지 않는다. 기존 버전보다 숫자가 줄어든 경우 문항이 새로 틀렸다는 뜻은 아니며, 상태 주장과 근거 확인의 차이를 먼저 살핀다. 순환·부모 누락·손상·내용 변경은 조회 결과에 이유를 남기고 원 파일은 보존한다. `last_saved_review`는 수정 중에도 확인할 수 있는 마지막 직접 검토의 이력이고, 현재 후보와의 연결 여부는 `review_provenance`에서 따로 확인한다.

이 검사는 저장 자료의 연결을 점검한다. 검토자의 실제 신원·전문성, 목표 난도·변별도, 사람 승인이나 한글 인쇄 배치를 인증하지 않는다.

### 검토 뒤에 추가한 의견

`feedback --candidate-sha 검토한해시`로 추가한 문항 의견도 재개 입력에 연결한다. 원 run의 마지막 `review-rN.json`에 오류가 없어도, 현 후보에 연결된 후속 A/B 의견이 있으면 새 실행은 수정부터 시작한다. C 의견은 출제·편집 참고로 전달하며 C만으로 선행 수정을 강제하지 않는다. 의견은 검토할 자료이며 자동으로 정답이나 새 규칙이 되지 않는다.

후속 의견의 원문·작성 주체·문항 ID·후보 해시와 원 파일·행 연결을 별도로 보존한다. 이전 검토 파일을 고쳐 나중 의견을 당시 검토처럼 만들지 않는다. 다른 run이나 이전 후보의 의견을 현 초안에 섞지 않으며, 재개 초안이 의견 대상 후보와 다르면 먼저 버전 관계를 확인해야 한다. 블라인드 풀이자는 이 의견과 정답 근거를 받지 않는다.

수정본 저장 뒤 독립 풀이·편집이 중단됐으면 이전 의견을 **과거 검토 근거**로 편집자에게 전달한다. 이를 새 후보에 확정된 오류로 붙여 수정부터 강제하지 않는다. 새 편집 검토가 저장된 뒤에는 그 결과를 다음 판단의 근거로 사용한다. 실행기 연결 전에 실패한 경우도 상속 초안·검토를 남겨 다시 이어갈 수 있다.

`needs_revision`만 보고 수정이 완료됐다고 판단하지 않는다. 새 후보에는 새 풀이·편집 결과가 필요하고, 알려진 구조 반복을 고칠 때는 같은 과거 원문과 결정적 추론·오답 역할을 다시 비교한다. 문자 유사도 검색의 flag가 0이어도 의미상 반복이 없다는 뜻은 아니다.

이 전달 경로는 일반·composition 재개의 합성 회귀와 전체 1,249개 테스트로 확인했다. 별도의 실제 연결 시험에서는 보존된 PSAT 7급 상황판단 2문항 중 1문항을 수정하고 새 풀이·편집·진단 평가까지 CLI 4회로 실행했다. 두 정답이 일치했고 편집 A/B 0건·기존 C 2건이 남았다. 이 국소 실행은 과거 composition의 자동 재개나 전체 회차 완성, 전문가 승인, 장기 반복 감소의 입증이 아니다. 과거 봉인을 새 실행에 복사하지 않아 진단 평가의 검토 연결은 미확인 상태로 유지했다.

### 원 검토본을 보존한 수정 요청

종료한 검토본의 상태까지 보존하거나, C급 편집 의견을 실제로 반영하고 싶으면 `exam-revision-request`로 별도 요청을 만든다. 기존 `feedback` 명령은 원 run의 상태와 인접 의견 파일을 갱신한다. 새 요청 명령은 이를 변경하지 않으며 모델도 호출하지 않는다.

```sh
./haean tools exam-revision-request runs/example/production-v1 \
  --out runs/example/revision-request.json --slots 2 22 \
  --file runs/example/revision-note.txt --reviewer '편집 검토 모델' \
  --origin model --severity C
./haean tools exam-resume runs/example/production-v1 \
  --out runs/example/production-v2 --slots 2 22 \
  --revision-request runs/example/revision-request.json --workers 1 --max-revisions 0
```

의견 파일에는 고칠 구절·이유·유지할 조건을 적는다. 짧은 의견은 `--text`로 넣어도 된다. 번호는 기존 작성 묶음 전체여야 하며 요청 파일은 검토한 후보·배정·원 실행에 연결된다. 원 검토본 밖의 새 파일로 저장한다. 모델 의견은 `--origin model`로 기록하고, 실제 사람 의견을 옮겼을 때만 `human`으로 쓴다. 이 명령은 의견 등록과 **이번 수정의 명시적 요청**을 함께 기록하므로 C도 수정부터 시작한다. C를 A/B 오류로 승격하지 않으며, 기존 C 의견만으로는 자동 수정을 강제하지 않는다.

재개에는 `--slots`가 필요하고, 요청의 모든 번호가 선택 범위 안에 있어야 한다. 서로 다른 묶음의 요청 파일은 `--revision-request`를 반복해 전달할 수 있다. 같은 묶음의 중복 요청, 다른 회차·변경된 후보·깨진 해시·부분 묶음, `--replacement` 병용은 실행 전에 거절한다. 새 요청을 만들었다고 원 회차의 검토 상태가 바뀌지는 않는다. 원 후보에 이미 연결된 기존 의견은 새 요청과 함께 전달한다.

요청 이후에는 새 수정·독립 풀이·편집을 수행한다. 위 예시의 `--max-revisions 0`은 요청된 첫 수정 뒤 추가 자동 수정 없이 검토 결과를 남긴다는 뜻이다. 실패나 미해결 오류가 있으면 그 기록을 보존한다. 새 검토가 저장된 뒤에는 과거 요청을 계속 재적용하지 않는다. 수정 뒤 풀이·편집이 중단된 경우에는 요청을 이전 버전의 검토 자료로 전달한다. 요청 생성은 승인이나 오류 해결의 증거가 아니며, 사람이 수집한 검토 파일을 자동으로 승인·반영하는 기능도 아니다.

실제 PSAT 5급 언어논리 검토본에서도 C 요청으로 한 묶음을 수정하고 새 풀이·편집·진단 평가까지 CLI 4회를 실행했다. 수정 요청의 작성·편집 입력 전달과 학생용 문면만 포함한 독립 풀이 입력을 확인했고, 40문항 중 1문항만 변경되고 나머지 39문항과 원 실행 파일은 보존됐다. 새 검토에서는 두 정답이 일치하고 편집 지적이 없었지만, 일부 오답의 유인력과 목표 난도는 추가 확인이 필요하다. 평가의 저장 검토 연결은 `unverified`, `eligible=false`로 유지했다. 이 기록은 국소 수정 경로의 실행 증거이며 전문가 승인·회차 전체 품질 향상·한글 배치 확인을 뜻하지 않는다.

## 외부 회차 설계를 사용한 실행 재개

`--composition-packet`으로 만든 회차도 위의 같은 `exam-resume` 명령을 사용한다. 새 출력 경로에 원 배정표 바이트와 설계 연결을 유지하며, 원 실행 파일은 수정하지 않는다. 모든 문항의 번호·ID·묶음·공통지문과 설계·출처·검토 해시를 먼저 대조한다. 입력이 바뀌거나 연결이 누락되면 모델 호출 전에 거절한다.

완료 묶음은 후보와 검토 원문이 해당 설계에 연결되어 있는지 확인한 뒤 재사용한다. 미완료 묶음은 원래 묶음 단위를 유지하며, 저장된 초안·검토 지적·참고자료를 새 실행에 연결한다. 초안만 있고 검토가 없으면 새 독립 검토부터 진행한다. 검토 기록이 있는데 해당 버전의 연결 증거가 없거나 달라졌다면 자동 재사용하지 않는다. 새 수정에서도 설계 검증을 수행하고 독립 풀이에는 제작 설계·정답·이전 검토를 전달하지 않는다.

처음 수정 호출이 중단되어 상속 초안만 남은 실행도 원본 경로·해시·검토 연결을 확인해 다시 이어갈 수 있다. 실패 기록을 지우거나 상속 파일을 새 검토 완료 증거로 취급하지 않는다. 재개 실행은 새로운 호출·수정 예산을 사용하므로 기존 실행과 사용량을 따로 기록한다.

이 경로에서는 `--replacement`를 지원하지 않는다. 별도 묶음을 섞으려면 동일 설계·배정·검토 연결을 보장하는 별도 계약이 필요하다. 일반 회차의 기존 대체 묶음 기능은 그대로다. `production.json`이 없거나 전체 문항 배정이 누락된 실행은 정상 재개 대상이 아니며, 남은 파일을 보존하고 원인을 먼저 확인한다.

설계에 기록된 코드·규칙 해시가 현재 환경과 다르면 재개를 거절한다. 업데이트 전 설계의 해시를 새 값으로 고쳐 통과시키지 않는다. 원 실행 당시의 코드와 입력이 보존된 환경에서 재개하거나, 새 설계를 검토하여 별도 새 회차로 시작한다. 재개 성공은 전문가 승인·난도 검증·한글 인쇄 확인을 뜻하지 않는다.
