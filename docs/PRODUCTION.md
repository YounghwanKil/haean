# 모의고사 생성과 재개

이 문서는 추리논증·PSAT의 `exam-build` 경로다. 언어이해는 [지문별 제작](READING_PRODUCTION.md)의 `reading` 명령으로 3문항 세트 작성·검토·이어하기를 관리한다.

`exam-build`는 배정표에서 전체 회차를 만든다. `exam-resume`은 중단된 실행의 문항·검토 이력을 남겨 두고 새 출력 경로에서 이어간다.

```sh
./haean tools exam-build runs/example/assembly.json --out runs/example/production-v1 --workers 3
./haean tools exam-status runs/example/production-v1
./haean tools exam-resume runs/example/production-v1 --out runs/example/production-v2 --workers 3
./haean tools exam-assemble runs/example/production-v2
```

생성이 오래 걸릴 때 다른 터미널에서 `exam-status`로 묶음별 마지막 요청 단계, 오류와 검토 버전 해시가 일치하는 문항 수를 확인한다. 이 명령은 모델을 호출하거나 작업을 재시작하지 않는다. `last_requested_stage`는 요청 기록이며 해당 단계의 완료나 프로세스 생존을 뜻하지 않는다. 실행 중인 원래 터미널과 함께 확인한다. 모델 검토 수는 전문가 승인·한글 인쇄 검증 수가 아니다.

수정이 진행 중이면 `last_saved_review`에서 수정 전 마지막 검토의 A/B 오류와 C 의견을 볼 수 있다. 새 초안이 생성됐다는 이유만으로 이전 오류를 해결 처리하지 않으며, 다음 검토가 저장되면 표시가 갱신된다.

모델 검토를 마친 후보는 해시와 ID 순서를 확인해 재사용한다. 미완료 묶음에 저장된 초안이 있으면 마지막 초안과 그 버전의 텍스트 지적을 새 run으로 전달한다. 초안 없이 중단된 일반 묶음은 최대 2문항으로 나누며 공통지문 세트는 유지한다. 기존 초안의 참고자료를 소급 교체하지 않는다. 새 실행의 블라인드 풀이에는 정답·해설·이전 검토를 전달하지 않는다.

별도 복구 실행을 이미 마쳤다면 `--replacement RECOVERY.json`을 사용할 수 있다. 해당 JSON의 `jobs`는 `run`, `ids`, `slots`를 가져야 하고, 대체하려는 기존 묶음의 ID 전체를 중복 없이 포함해야 한다. 원래 실패한 묶음과 복구 문항을 동시에 회차에 넣지 않는다. 외부 출처의 JSON은 실행 명령이 아니다.

배정표의 중하·중상 같은 세부 난도는 원문대로 남기되 공통 `Brief`의 하·중·상 필드에는 중으로 전달한다. 실제 출제자는 개별 배정과 난도 근거를 읽어 설계한다. 배정표·실제 초안·검토 상태의 차이를 최종 구성 검토에서 확인한다.

재개 결과의 `complete`는 모든 묶음이 모델 검토 후 사람 검토를 기다린다는 뜻이다. 전문가 승인이나 HWP 인쇄 검증을 뜻하지 않는다. `assembled.json`의 누락·공통지문·필수 도표 오류도 별도로 확인한다. `production.json`과 각 run의 상태·원문·사용량·해시를 함께 보존한다. 이전 실행과 입력이 달라지면 이를 고정 평가의 성능 향상 증거로 사용하지 않는다.

### 검토 뒤에 추가한 의견

`feedback --candidate-sha 검토한해시`로 추가한 문항 의견도 재개 입력에 연결한다. 원 run의 마지막 `review-rN.json`에 오류가 없어도, 현 후보에 연결된 후속 A/B 의견이 있으면 새 실행은 수정부터 시작한다. C 의견은 출제·편집 참고로 전달하며 C만으로 선행 수정을 강제하지 않는다. 의견은 검토할 자료이며 자동으로 정답이나 새 규칙이 되지 않는다.

후속 의견의 원문·작성 주체·문항 ID·후보 해시와 원 파일·행 연결을 별도로 보존한다. 이전 검토 파일을 고쳐 나중 의견을 당시 검토처럼 만들지 않는다. 다른 run이나 이전 후보의 의견을 현 초안에 섞지 않으며, 재개 초안이 의견 대상 후보와 다르면 먼저 버전 관계를 확인해야 한다. 블라인드 풀이자는 이 의견과 정답 근거를 받지 않는다.

수정본 저장 뒤 독립 풀이·편집이 중단됐으면 이전 의견을 **과거 검토 근거**로 편집자에게 전달한다. 이를 새 후보에 확정된 오류로 붙여 수정부터 강제하지 않는다. 새 편집 검토가 저장된 뒤에는 그 결과를 다음 판단의 근거로 사용한다. 실행기 연결 전에 실패한 경우도 상속 초안·검토를 남겨 다시 이어갈 수 있다.

`needs_revision`만 보고 수정이 완료됐다고 판단하지 않는다. 새 후보에는 새 풀이·편집 결과가 필요하고, 알려진 구조 반복을 고칠 때는 같은 과거 원문과 결정적 추론·오답 역할을 다시 비교한다. 문자 유사도 검색의 flag가 0이어도 의미상 반복이 없다는 뜻은 아니다.

이 전달 경로는 일반·composition 재개의 합성 회귀와 전체 1,249개 테스트로 확인했다. 별도의 실제 연결 시험에서는 보존된 PSAT 7급 상황판단 2문항 중 1문항을 수정하고 새 풀이·편집·진단 평가까지 CLI 4회로 실행했다. 두 정답이 일치했고 편집 A/B 0건·기존 C 2건이 남았다. 이 국소 실행은 과거 composition의 자동 재개나 전체 회차 완성, 전문가 승인, 장기 반복 감소의 입증이 아니다. 과거 봉인을 새 실행에 복사하지 않아 진단 평가의 검토 연결은 미확인 상태로 유지했다.

## 외부 회차 설계를 사용한 실행 재개

`--composition-packet`으로 만든 회차도 위의 같은 `exam-resume` 명령을 사용한다. 새 출력 경로에 원 배정표 바이트와 설계 연결을 유지하며, 원 실행 파일은 수정하지 않는다. 모든 문항의 번호·ID·묶음·공통지문과 설계·출처·검토 해시를 먼저 대조한다. 입력이 바뀌거나 연결이 누락되면 모델 호출 전에 거절한다.

완료 묶음은 후보와 검토 원문이 해당 설계에 연결되어 있는지 확인한 뒤 재사용한다. 미완료 묶음은 원래 묶음 단위를 유지하며, 저장된 초안·검토 지적·참고자료를 새 실행에 연결한다. 초안만 있고 검토가 없으면 새 독립 검토부터 진행한다. 검토 기록이 있는데 해당 버전의 연결 증거가 없거나 달라졌다면 자동 재사용하지 않는다. 새 수정에서도 설계 검증을 수행하고 독립 풀이에는 제작 설계·정답·이전 검토를 전달하지 않는다.

처음 수정 호출이 중단되어 상속 초안만 남은 실행도 원본 경로·해시·검토 연결을 확인해 다시 이어갈 수 있다. 실패 기록을 지우거나 상속 파일을 새 검토 완료 증거로 취급하지 않는다. 재개 실행은 새로운 호출·수정 예산을 사용하므로 기존 실행과 사용량을 따로 기록한다.

이 경로에서는 `--replacement`를 지원하지 않는다. 별도 묶음을 섞으려면 동일 설계·배정·검토 연결을 보장하는 별도 계약이 필요하다. 일반 회차의 기존 대체 묶음 기능은 그대로다. `production.json`이 없거나 전체 문항 배정이 누락된 실행은 정상 재개 대상이 아니며, 남은 파일을 보존하고 원인을 먼저 확인한다.

설계에 기록된 코드·규칙 해시가 현재 환경과 다르면 재개를 거절한다. 업데이트 전 설계의 해시를 새 값으로 고쳐 통과시키지 않는다. 원 실행 당시의 코드와 입력이 보존된 환경에서 재개하거나, 새 설계를 검토하여 별도 새 회차로 시작한다. 재개 성공은 전문가 승인·난도 검증·한글 인쇄 확인을 뜻하지 않는다.
