# 기존 HWP 양식 삽입

LEET와 PSAT은 사용자가 지정한 대로 같은 편집 틀을 쓴다. 시험명·과목명과 문항 내용을 바꾸고, 원본의 용지·다단·제목 영역·보기 박스·이름 있는 스타일을 보존한다. `skills/haean-layout/SKILL.md`가 작업 절차다.

## 설치와 실행

`./haean setup-layout`은 도형 렌더용 Python 패키지를 프로젝트 가상환경에 설치하고, hwp-cli 1.3.1과 hwplib 1.1.11을 SHA-256으로 확인해 `data/bin`에 설치한 뒤 Java 코드를 컴파일한다. JDK 17 이상이 필요하다. 현재 macOS ARM/x64 및 Linux ARM/x64를 지원한다. 폰트는 원본 제공 파일을 `data/fonts`에서 사용한다. 원문·폰트를 Git에 넣지 않는다.

논증 도식은 Graphviz의 `dot`으로 선이 노드·결합점을 피해 가도록 배치하고 Matplotlib로 그린다. macOS는 `brew install graphviz`, Linux는 `apt install graphviz`가 필요하다. 선택지들의 공통 배치를 한 번 계산해 위치 자체가 정답 단서가 되지 않게 한다. 지지는 실선 화살표, 공격은 점선의 막대 끝이다. 논증 figure.note는 편집 메모로 검증 기록에 보존하고, 응시자에게 필요한 규칙은 지문에 둔다. 자료 그래프의 note는 수치·단위 주석이므로 그림에 표시한다.

```sh
./haean tools layout-fill RUN --template QUESTIONS.hwp --out runs/example/questions.hwp --title '해안 LEET 추리논증 검토용'
./haean tools layout-fill RUN --template SOLUTIONS.hwp --out runs/example/solutions.hwp --title '해안 LEET 추리논증 검토용' --kind solutions
```

RUN을 여러 개 지정하면 해당 순서대로 넣는다. `--start 5`는 5번부터 채운다. PSAT은 제목만 예컨대 `해안 PSAT 5급 상황판단 검토용`으로 바꾸며 과목명은 brief에서 가져온다. 제목 영역과 바탕쪽·머리말의 과목명을 함께 바꾼다.

현재 지원하는 마스터는 제공 자료의 `40문항(20p)양식_260804_0000_v3.hwp`와 `40문항해설지양식_250928_2226_v3 (3).hwp`다. Java가 실제 자리표시자 40개를 확인한다. 완성 문제지를 빈 마스터로 잘못 넣으면 거부한다. 최신 CA 완성본을 이용한 스타일·배치 비교는 별도 과제이며 동일 파일이라고 주장하지 않는다.

문제지는 발문·지문·보기·선지·표 셀을 채운다. 원본의 편집 예시 표는 제거한다. 해설지는 두 정답표와 문항별 정보 상자에 같은 candidate의 정답·난도·유형을 넣고, 해당 해설 블록에 해설과 선지별 판단을 추가한다. 예시 정답·회차 총평은 제거한다. 미작성 슬롯은 receipt에 남긴다.

해설지 마스터의 편집 메모 필드와 메모 목록은 출력 복사본에서 함께 정리한다. 문단만 삭제하고 원본 메모 참조를 남기면 Java 재읽기가 성공해도 한글에서 손상 문서가 된다. 원본 파일은 수정하지 않는다. 사용자 피드백에 따라 정답 원문자는 10pt·장평 100%로 출력한다. 해설 문항 번호는 원본 스타일의 자동 번호를 사용한다.

## 검증 범위

문항의 `commentary`에는 출처 정정·배정 변경 등 제작 이력이 섞일 수 있으므로 학생용 HTML·HWP 해설에는 넣지 않는다. 정답 근거와 선지별 설명은 그대로 출력하며 코멘트 원문은 candidate.json에 보존한다.

첫 문항의 지문·보기 상자는 단 경계에서 나누지 않는다. 한글 2014에서 첫 쪽 오른단으로 이어지는 표 셀이 제목 영역과 겹치는 현상을 방지하기 위한 처리다. 첫 문항 상자 자체가 한 단보다 길면 별도 배치 조정과 실제 재출력이 필요하며, 이후 문항의 긴 상자는 기존처럼 나눌 수 있다.

`layout-fill`은 원본/문항 해시, 작성 슬롯과 미작성 슬롯을 기록하고 출력 파일을 재읽어 내용 누락을 검사한다. 해설지는 표지 정답표·본문 정답표·40개 해설의 정답 상자를 같은 정답 맵과 대조하고, 불일치나 누락 시 오류를 낸다. receipt에 번호별 실제 정답과 재읽기 결과를 남긴다. 원본과 기존 출력은 덮어쓰지 않는다. 자동 검사는 `layout_verified=true`나 납품 승인을 만들지 않는다.

2026-10-07 현재 LEET 1문항과 PSAT 자료해석 1문항을 각자 원본 마스터에 삽입해 한컴오피스 한글 2014 VP에서 열었다. LEET 본문·보기·선지와 PSAT 실제 수치 표를 시각 확인했다. 40문항 마스터의 미작성 슬롯이 남은 샘플이며 전체 회차 인쇄 검증과 재현율 99% 측정은 완료하지 않았다. 해설지·반복 머리말·전체 페이지 확인 기록은 로컬 출력과 함께 별도로 보관한다.

LEET 해설지 v7은 한글에서 열고 한글 인쇄 엔진으로 PDF 22페이지를 생성했다. 채워진 1문항이 있는 표지와 2페이지에서 정답 크기·정보표·해설을 확인했다. 나머지 39문항이 미작성인 양식 테스트이며 전체 회차가 완성됐다는 뜻이 아니다.

PSAT 자료해석 해설지 v7도 별도로 열어 PDF 22페이지를 생성하고 과목명·정답·해설 배치를 확인했다. 추가로 40개 합성 번호를 넣은 양식 전용 시험에서 두 정답표와 40개 정보 상자의 저장 후 대조를 통과하고, 한글 화면과 PDF에서 앞 정답표의 1–40번을 확인했다. 이 합성 데이터는 실제 모의고사의 정답으로 사용하지 않는다.

40문항 틀을 7급 25문항 또는 브릿지 20문항으로 확정할 때는 문항 수 안내, 여백, 전체 페이지, 마지막 문항까지 함께 조정해야 한다. 구조화된 논증 도식·막대/선 그래프는 PNG/SVG로 만들고 HWP에 이미지로 삽입한다. 합성 막대그래프의 실제 한글 삽입을 확인했으며, 실제 문항 도형의 정보 보존·가독성은 문항마다 확인해야 한다. 수식 객체 자동 제작은 현재 지원하지 않는다. 글자 수 증가로 생긴 넘침은 실제 한글 렌더에서 확인한다.

Rust 엔진으로 새 HWP를 조립한 초기 실험은 자체 재읽기는 성공했지만 한글에서 정상 표시되지 않았다. 제품 출력 경로는 검증한 hwplib 원본 삽입으로 바꿨다. Rust 렌더는 원본 한글의 조판과 일치하지 않을 수 있으므로 보조 검사로만 사용한다.

MCP는 `scripts/hwp_mcp.py`에서 프로젝트 폴더를 루트로 실행한다. initialize와 tools/list 응답을 실제 확인했다. 이는 현재 대화의 도구 목록에 자동으로 추가됐다는 뜻은 아니다. Codex에서 프로젝트를 다시 열 때 연결되며 API 키가 필요하지 않다.

기존 `layout-package`는 외부 도구에 전달할 해시 manifest만 만든다. 승규님의 Java 소스는 전달받지 못했으며, 이번 구현은 공개 hwplib를 이용한 별도 어댑터다.

엔진 출처: [hwp-cli](https://github.com/STAIxBWLB/hwp-cli), [hwplib](https://github.com/neolord0/hwplib). 실행 바이너리와 JAR은 로컬 설치하며 원본 라이선스를 따른다.

## 실제 전체 쪽 수 보정

내용이 길거나 도식이 들어가면 원본 20쪽을 넘을 수 있다. 먼저 한글 인쇄 엔진으로 PDF를 만들고 실제 쪽 수를 확인한다. 그 다음 같은 문항으로 새 파일을 만들 때 `--total-pages 21`처럼 지정하면 문제지 첫 쪽과 홀수·짝수 바탕쪽의 전체 쪽 수 세 곳만 바꾼다. 본문의 수치 `20`은 바꾸지 않는다. 재출력한 PDF 쪽 수가 같은지 다시 확인해야 하며, 숫자만 바꾼 것을 넘침 해결로 취급하지 않는다.

```sh
./haean tools layout-fill RUN --template QUESTIONS.hwp --out runs/example/questions-pages.hwp --title '해안 LEET 추리논증 검토용' --total-pages 21
```

실제 LEET 논증구조 23번의 도식 삽입을 확인했다. 별도의 PSAT 언어논리 40문항 검토본은 한글 PDF 22쪽으로 출력하고 첫 쪽을 포함한 22쪽 전부의 분모가 22로 바뀌었으며 본문 텍스트는 변하지 않았음을 대조했다. 도식 글자의 실제 시험 가독성과 문항 품질은 사람 확인이 남아 있다.

## 공통지문과 긴 상자

실제 출력에서 본문과 도식이 서로 다른 쪽으로 갈라지면 `--page-start 23`처럼 해당 문항을 새 쪽에서 시작시킬 수 있다. 출력에 포함된 2번 이후 문항만 지정하며, 공통지문의 두 번째 문항만 분리하는 지정은 거부한다. 지정 슬롯은 receipt에 남는다. 새 쪽 시작으로 전체 쪽 수가 바뀔 수 있으므로 재출력 후 `--total-pages`와 전체 배치를 다시 확인한다.

인접한 두 문항의 shared_passage_id·지문·표가 같으면 공통지문을 한 번만 출력하고 [19~20]처럼 안내한다. 첫 문항 발문은 공통지문 뒤로 옮기며 두 번째 문항의 고유 보기·그림은 유지한다. 지문·표가 다르거나 두 문항이 인접하지 않으면 임의로 합치지 않고 오류를 낸다. 단일 문항 검토용 출력에는 지문을 생략하지 않는다.

채운 지문·보기 상자는 글자처럼 취급하는 고정 개체 대신 본문 공간을 차지하며 쪽·단 경계에서 나눌 수 있게 한다. 공백 줄의 중복만 제거하고 문단 경계·글자·조건은 보존한다. 원본의 불필요한 강제 쪽 나눔은 단 나눔으로 바꾸고, 공통지문의 두 번째 문항은 이어서 배치한다. PSAT 언어논리 실물 검증에서 이전 26쪽 출력의 용지 밖 텍스트가 수정본 22쪽에서 사라진 것을 확인했다. 경계 검사만으로 가독성·줄바꿈까지 합격이라고 하지 않으며 전체 페이지 시각 검토를 별도로 남긴다.

긴 선지는 다섯 개의 독립 문단으로 삽입하고 보기·선지의 한 문단이 한 줄만 다음 단에 남지 않게 보호한다. 해설의 선지 판단 표제는 다음 설명과 함께 배치한다. PSAT 표지의 LEET 교시 표시는 ‘모의고사’로 바꾸며 원본 HWP의 고정폭 공백 제어 문자도 처리한다. 공식 PSAT 교시를 추정해 넣지 않는다. Java 소스 업데이트 후 `./haean setup-layout`으로 다시 컴파일해야 한다.

전체 PSAT 언어논리 40문항은 문제지 22쪽·해설지 26쪽을 한글 인쇄 엔진으로 출력해 전 페이지를 검토했다. 실제 정답표 두 곳의 40개 답안이 일치하고 약 10pt로 표시되는 것을 PDF에서도 확인했다. 이는 양식 검증이며 문항의 전문가 승인이나 99% 재현율 측정이 아니다. 긴 문항의 단 넘김과 인쇄 가독성은 최종 편집에서 확인한다.

## 자료 그래프와 보기 그림

수치 그래프의 `y_min`·`y_max`·`y_ticks`는 표시 축을 고정한다. 비교 가능한 그래프 선지는 공통 축을 쓰며 서로 모순되는 명시 축은 거부한다. `show_values`로 정확한 수치를 표시할 수 있고, `layout_note`는 편집 기록에만 남긴다. 수험생에게 필요한 단위·주석은 `note`에 쓴다. 논증 도식의 기존 메모도 공개 입력과 문제지에 노출하지 않는다.

자료 그래프 선지는 한 열에 배치하고 범례를 그래프 위에 둔다. 논증 도식 선지는 기존 두 열을 유지한다. `placement=statements`인 그림은 보기 표의 제목 셀이 아닌 본문 셀에 넣고 셀 안쪽 너비에 맞춘다. 다섯 그림만으로 구성된 선지에는 원문자만 있는 빈 선지 행을 중복 인쇄하지 않는다.

PSAT 자료해석 25번 및 공통지문 35–36번은 이 경로로 실제 한글 PDF를 출력하고 수치·축·범례·보기 그림 잘림을 재검토했다. 새 Astra 독립 풀이와 편집 검토에서 A/B 오류가 남지 않았으며, 사람 확인은 별도다. 이는 해당 문항의 검토 기록이며 모든 그래프의 자동 시각 합격을 뜻하지 않는다.
