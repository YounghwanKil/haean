# LEET 추리논증 편집 후보

이 변경은 사람의 출력물 검토에서 반복된 제작 문제를 다루는 후보다. 실제 모델 비교 전이며 출제 점수·전문가 채택률이 향상됐다고 주장하지 않는다. 평가 프로토콜과 채점 코드는 그대로 둔다. 검토 원문과 문항별 수정안은 로컬 자료에 보존하고, 공개 코드에는 제작 원칙과 합성 검사만 둔다.

## 실제 연결

- `prepare`의 LEET 추리논증 요청에는 `leet_editorial.md`가 포함된다. 선택 근거를 기존 `design_summary`에 남기도록 `editorial-plan.json`을 만들고 동일 내용을 `context.json`·`request.md`에 넣는다.
- 자동 생산의 writer와 editor, 수동 `check`가 만드는 `editorial-instructions.md`가 같은 제작·편집 지침을 사용한다. 블라인드 입력에는 설계 메모를 넣지 않는다. PSAT 여섯 제품군과 별도 언어이해 경로에는 이 지침을 넣지 않는다.
- 회차 생산은 각 묶음에 전체 슬롯의 소재·인지 과제 개요를 전달한다. 소재와 판단 구조가 함께 반복되는지 다른 묶음까지 대조할 수 있다. 정답 목표와 다른 문항의 정답·해설은 이 개요에 넣지 않는다. 배정표가 의미상 중복을 증명하지는 않으며, 배정 충돌은 총괄에게 반환한다.
- 조건 삭제·선지 이관·용어와 주체 기호 변경은 모든 선지와 해설의 의미 검토로 묶는다. 문자열에 따른 자동 삭제나 발문 일괄 치환은 하지 않는다.

## 변경 근거와 범위

길이와 정의가 늘어도 실제 판단은 규칙 하나의 대입으로 끝날 수 있다. 핵심 추론을 쓰지 않아도 정답이 남는지, 오답에서 주장한 실수가 실제 판정을 바꾸는지를 따로 확인한다. 예컨대 합성 규칙에서 예외 조건을 바꿔도 우선 규칙 하나가 항상 승자를 결정하면, 예외를 더 쓰는 대신 경쟁 상황을 재설계해야 한다.

단서를 삭제해 간결하게 만들 때는 논리 조건을 잃을 수 있다. 합성 사례에서 표본 구성이 달라져도 집단별 성공률이 유지된다는 전제가 특정 보기에 필요하다면 그 보기로 옮기고 원문 삭제와 함께 검토한다. 정의·측정 오차·새 정보 유무 역시 표면상 부연이라는 이유로 제거하지 않는다.

발문은 보기가 요구하는 실제 판단과 맞춘다. 분석은 견해의 귀결과 증거 평가를 함께 다룰 수 있으므로 강화·약화 표현만으로 발문을 결정하지 않는다. 규정 표지를 택하면 도입부·발문·본문·선지에 같은 표지를 쓴다. 논증 도식은 관례적 읽기 설명을 덧붙이라는 기존 지침을 수정하고 진술 범위와 실제 도식 표현을 확인한다.

검토자가 지정한 강도·선택안·연동은 해당 피드백의 속성이다. 빈도·글자수·현재 양식의 줄 수와 첫 문항 유형 선호를 전체 시험의 법칙으로 확대하지 않는다. 형식 의견이 없는 문항의 정답이나 내용 품질도 별도로 검토한다.

## 퇴행 가능성과 검증

지침과 회차 개요가 추가되어 입력 토큰이 늘어난다. 조건 보존을 강조하다 과잉 안내가 다시 늘거나, 표면 형식에 맞추느라 좋은 분석 보기를 불필요하게 재작성할 수 있다. 구성 선호를 고정 할당으로 오인하거나 배정표만 보고 중복을 확정할 위험도 있다. 그래서 자동 교정·자동 불합격 기준으로 만들지 않고 선택 근거를 기록한다.

합성 검사는 `prepare`→요청/컨텍스트→writer/editor 전달, 수동 `check`, 전체 회차의 다른 묶음 개요 전달, 블라인드 정보 분리, PSAT 비적용을 확인한다. 이는 모델이 지침을 잘 따르거나 점수가 오른다는 검증을 대신하지 않는다. 후보 비교는 같은 모델·동결 입력·수정 예산 아래 초안과 최종 원문, 독립 풀이, 비용을 함께 확인해야 한다. 논리 검토 후 윤문하고 전 선지·해설을 다시 검토한다. HWP 렌더 확인은 별도 계약을 따른다.
