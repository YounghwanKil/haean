# 실행 기록을 이용한 개선 후보 진단

`evolve-reflect`는 기존 실험의 조건·품질 차원·사용량·실패 원문을 한 보고서로 연결한다. [GEPA](https://arxiv.org/abs/2507.19457)의 텍스트 피드백·다목적 후보 비교와 [Meta-Harness](https://arxiv.org/abs/2603.28052)의 실행 원문을 찾아 읽는 방식을 참고했다. 두 논문의 전체 탐색 알고리즘을 구현하거나 성과를 재현했다는 뜻은 아니다.

```sh
scripts/haean-tool evolve-reflect experiments/example/baseline/results.json \
  experiments/example/candidate/results.json \
  --comparison experiments/example/comparison.json \
  --evidence-root experiments/example \
  --out experiments/example/reflection-01.json
```

명령 자체는 모델을 호출하지 않는다. [스킬 사용 지침](../skills/haean-evolve/references/reflection.md)에 입력 조건과 다음 실험 절차가 있다. 원문·결과·진단 보고서는 로컬 자료이며 Git에 올리지 않는다.

## 이번에 개선한 부분

- 양쪽 기록에 조건이 없으면 동일 조건으로 인정하지 않는다. 중복·누락·실패 행도 보고서에 남기고 비교 가능 판정을 보류한다.
- 8개 품질 차원과 호출 수·시간·토큰을 따로 비교한다. 품질은 좋아졌지만 비용이 커지는 경우도 표시한다. 평균 차원 변화와 함께 개별 사례의 하락을 남긴다.
- 유효성 실패와 치명 오류는 높은 다른 점수로 상쇄하지 않는다. 누락된 사용량은 0이 아닌 미확인 값이다.
- 원문 경로·현재 관측 SHA256·JSON 위치·수정 차수를 연결한다. 중간 검토 의견을 최종 미해결 오류라고 단정하지 않는다.
- `exam/subject`와 `track/grade` 구조를 구분해 읽고, 과목·급수가 다른 짝을 차단한다. 원본 manifest는 변환하거나 보충하지 않는다.
- holdout으로 표시된 입력과 명시한 실험 폴더 밖 원문은 읽지 않는다. 기존 출력은 덮어쓰지 않으며 평가기·점수·채택 판정은 변경하지 않는다.

두 후보의 차원별 우열·교환관계를 진단하는 기능이며, 자동 승격이나 다수 후보의 진화 탐색은 아니다. 전체 문항의 전문가 품질을 보장하지 않는다.

## 2026-10-20 확인 결과

과거 개발 실험 12회(6짝)를 읽어 79개 원문 파일을 연결했다. 양쪽의 평가 프로토콜 표기 결손으로 새 비교 가능 판정은 보류했다. 이전 `reject_regression` 판정은 유지했다. 48→52호출이라는 비용 차이와 제품별 차원 하락도 보존했다. 이는 새로 실행한 문항 품질 비교가 아니다.

Codex 구독 세션에서 `gpt-6-astra`를 지정해 원인 분석을 1회 실행했다. 새 문항 생성은 0회다. 분석이 인용한 원문 3개는 문자열 대조를 통과했다. 모델 사용량은 입력 62,569·출력 1,823토큰, 호출시간 약 45.7초이며, 기록된 도구 실행은 0회다. 요청 모델과 실제 백엔드 모델의 별도 검증 여부는 구분한다.

분석에서 나온 계산식 중복 축약은 **다음 실험 가설**로 보관했다. 출제 기본 지침으로 승격하지 않았으며, 평가 한도를 완화하거나 기존 실패를 통과로 바꾸지 않았다. 문항 품질 향상·전문가 검증·한글 출력 개선은 이번 진단 작업에서 새로 입증한 결과가 아니다.
